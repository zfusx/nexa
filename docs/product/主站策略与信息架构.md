# Nexa 主站策略与信息架构

版本说明：本文件保留研究策略；v0.2 实现规格见 [页面与用户流程](页面与用户流程规格.md)。以下已按三题嵌入式体验和现有路由同步，未落地的账户/支付/资料管理不视为已实现。

## 主站必须完成的工作

主站不是产品说明书，也不是只用于品牌展示的海报。它必须让第一次听说 Nexa 的用户在短时间内完成四个认知动作：

1. 这是给像我这样有困惑、但不想被判词控制的人使用的。
2. Nexa 不只是聊天模型，它有明确的八字、易经和规则计算层。
3. 我可以先获得一点真实价值，不必先相信、注册或付费。
4. 结论可以追问、可以保留怀疑，最后仍由我作决定。

## 品牌消息架构

### 核心 Hook

> 对命运好奇，不等于把人生交给命运。

### 产品解释

> Nexa 是一个懂八字、会起卦、每个结论都可以追问“为什么”的 AI。它帮助你看懂自己正在经历什么，更笃定地选择下一步。

### 行动邀请

> 把那件悬着的事说出来。

### 信任承诺

- 不下判词。
- 不制造恐惧。
- 不替你决定。
- 区分计算、传统依据、AI 解释和现实建议。
- 在付费前交付一段完整、可读、可解释的价值。

## 首页结构

### 1. 导航

Logo、体验、测评、原理、关于、白皮书与“开始体验”主动作。导航使用短功能名；情绪化邀请保留在首页内容区，不放入全站导航。

### 2. Hero

- 主标题：对命运好奇，不等于把人生交给命运。
- 副标题：产品解释句。
- 主按钮：把那件事说出来。
- 次按钮：看看 Nexa 如何回答。
- 视觉：一个从复杂关系逐步收束为清晰路径的原创动态模型，不使用水晶球或廉价星空背景。

### 3. 问题入口

三张卡片：关系与相处、事业与选择、最近悬着的事。点击后滚动到首页三题体验，不自动代选答案。

### 4. 免费体验

问题围绕“当前更需要看清什么”而不是收集完整生辰。答案只在浏览器内使用，并明确这是产品交互示例，不是正式命理推演。

### 5. 结果示例

先完整展示：观察、可能的张力、现实下一步。随后允许展开：使用了哪些输入、为什么这样解释、哪些仍不确定。

### 6. 方法层

```text
八字：整理一个人的出发条件与长期结构
易经：理解当下正在发生的变化
计算系统：保证数据定义、规则和推演保持一致
AI：把复杂结果解释清楚，并承接继续追问
```

这里不展示商业机密公式，也不使用未经证实的“量子证明”表述。

### 7. 答案示例

使用真实产品风格的对话展示“结论—依据—现实建议—继续追问”，比功能 Logo 更能说明差异。

### 8. 品牌故事

从“有些事，光是说出口就需要勇气”开始，说明为什么 Nexa 选择认真回答。控制篇幅，不把完整五分钟故事全部塞进首页。

### 9. 信任与边界

说明隐私、记忆控制、危机情况、医疗/法律/投资边界、取消和退款原则。白皮书入口在这里出现。

### 10. FAQ 与最终 CTA

回答“准不准”“与普通 AI 有何区别”“会保存什么”“能否替我决定”“是否付费”等问题，再邀请进入正式产品。

## 轻量体验流程

| 步骤 | 内容                         | 目的                       |
| ---- | ---------------------------- | -------------------------- |
| 1    | 主题：关系 / 选择 / 悬着的事 | 降低空白输入压力           |
| 2    | 帮助：局面 / 时机 / 行动     | 决定结果侧重点             |
| 3    | 感受：看错 / 等待 / 后悔     | 形成追问句，不冒充命理输入 |
| 结果 | 观察、张力、行动与追问       | 注册前展示完整的理念示例   |

## 页面地图

```text
/
├── /#experience       首页内三题及结果（不是独立路由）
├── /quiz              广告/深链进入的独立 30 题测试与免费结果
├── /how-it-works      方法与产品分工
├── /story             品牌故事
├── /whitepaper        七章白皮书审阅稿与 PDF
├── /design-system     在线团队设计参考
├── /privacy           隐私说明
└── /terms             使用边界与免责声明
```

## 演示站非目标

- 不声称真实预测用户婚姻、健康或财务结果。
- 不收集出生时间、地点、手机号、邮箱或支付资料。
- 不连接生产账号、记忆或付费系统。
- 不制造假的用户数、准确率、媒体报道或评价。
- 不把竞品的配色、布局、图片或原文复制进 Nexa。

## 团队验收问题

- 新用户能否在首屏 10 秒内说出 Nexa 是什么？
- 用户能否在不注册的情况下完成一次有价值的体验？
- 页面是否清楚区分正式命理计算和演示体验？
- “为什么”是否比“神秘准确”更突出？
- 所有 CTA 是否说清下一步会发生什么？
- 是否存在任何让用户误解价格、数据使用或结果确定性的设计？
