# Nexa 团队交付入口

交付版本：v0.5 · 2026-09-14。对象：产品负责人、UI/UX 设计、前端、核心服务、QA、运维。

这是一套可以开工的主站设计与工程基线，不是已接通账户、命理计算和支付的完整商业产品。网站同时保留 v0.1 普通读者版和 v0.2 专业数学版白皮书，当前技术表达以 v0.2 为准；公开数学对象与验证逻辑不代表已经完成现实效果验证，设计样例也不是实证效果或用户案例。

## 先用十分钟认识项目

1. 打开 [整合演示站](https://main.zfis.net)，完成首页三题，查看结果、重选和重新体验。
2. 打开 [独立 30 题引流体验](https://main.zfis.net/quiz)，走完进度、返回、免费结果与重测流程。
3. 打开 [在线设计参考](https://main.zfis.net/design-system)，看色彩、排版、组件与未来异常状态的设计样例。
4. 打开 [方法白皮书](https://main.zfis.net/whitepaper)，理解技术表达和证据边界。
5. 依角色阅读下表文档，再按验收编号拆任务。不要把历史策略稿中的早期设想当成已实现需求。

## 三类状态，不混用

- **已实现**：八个静态路由、首页三题微体验、独立 30 题引流体验与免费结果、FAQ、白皮书阅读/PDF、在线设计参考。
- **生产版要求/建议**：真实报告、账户、支付、网络错误、任务状态、数据管理等。文档有设计与验收要求，但本演示没有这些服务。
- **待确认**：品牌源文件与完整授权归档、产品 URL、核心接口、价格与权益、数据政策、真实技术证据。负责人见决策清单。当前演示所用 Nexa 图标、星芒与两张产品背景图均已同域本地化。

“验收通过”只指文档与演示实现检查，不表示商业模式、命理有效性、法律合规或生产系统已经验收。

## 运行与复核

```sh
npm ci
npm run dev
npm run typecheck
npm test
npm run build
npm run format:check
```

以 `package-lock.json` 锁定版本。当前验证环境 Node.js 25；更换生产 CI 的 Node 版本需重新验证，不把本机环境视作长期支持承诺。Python 仅用于文档构建/检查，前端运行不依赖 Python。PDF 已随交付包提供，普通站点构建无须重生成它。

构建站点后可运行 `node scripts/check_site.mjs`；PDF 内容变化按 [工具指南](../../TOOLING_GUIDE.md) 再生成并检查。源码、公开文稿和 PDF 一并交付，不依赖原作者电脑里的内部技术资料。

## 交付物与边界

可移交的压缩包包含源码、依赖锁文件、公开文稿/PDF、交接文档、测试与发布说明。不包含 `node_modules`、Git 元数据、竞品录屏、内部技术文档、OCR、凭据或原始用户数据。包内清单提供 SHA256，便于接收方确认版本。

在线设计参考只是便于远程讨论的可视基线。演示已采用 Dev 产品正在使用的 Nexa 图标、星芒与背景图，但品牌源文件、完整授权归档、Figma 源文件、商用字体授权、最终隐私/订阅条款尚未提供，不能对这些事项宣称交付完成。
