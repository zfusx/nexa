# 实现与服务接入说明 v0.2

## 读前结论

当前可运行的是静态主站与本地规则微体验。不存在可直接用于真实命理、账户或收费的后端。本文件给出实现边界、替换位置及需要协商的契约，不是伪造的已上线 API 文档。

## 当前结构与数据流

| 层                      | 负责什么                                | 不负责什么               |
| ----------------------- | --------------------------------------- | ------------------------ |
| Astro 静态页面          | 首页、内容、SEO 元信息、白皮书/设计参考 | 登录态、计费、私密报告   |
| React 微体验            | 三题状态、返回、重置、焦点管理          | 远程计算、出生资料、LLM  |
| `buildExperienceResult` | 根据固定选项选取并组合文案              | 预测、概率、诊断、持久化 |
| React 引流测试          | 30 题进度、返回、重测、免费结果         | 广告追踪、账户、支付     |
| `buildQuizResult`       | 五维固定评分、反向题与结果文案          | 人格诊断、命理计算       |
| Markdown + PDF          | 单一公开内容源和离线阅读                | 内部公式/生产验证数据    |
| Caddy                   | TLS、静态文件与缓存、安全响应头         | 业务鉴权、付费权限       |

点击选择 → React 内存更新 → 本地函数组合文案 → 结果 UI。没有浏览器 fetch、XHR、WebSocket、localStorage、Cookie 追踪或账户写入。网页本身及静态资产请求仍会到达服务器；正式政策还需说明服务器访问日志，不能把“答案不上报”扩大成“服务器不处理任何访问数据”。

独立引流页入口为 `/quiz`。题库与评分在 `src/lib/acquisitionQuiz.ts`，交互在 `src/components/AcquisitionQuiz.tsx`，页面壳在 `src/pages/quiz.astro`。30 个答案仅存在 React 内存；完成后 `buildQuizResult` 对五个维度分别归一化并生成固定解释。当前 CTA 复用 `src/lib/site.ts` 的安全站内入口。生产接入广告归因、结果保存或账户时，必须先明确同意、数据最小化、保留期限和服务端契约，不能沿用当前内存数组作为生产数据模型。

## 已实现的本地接口

接口是 TypeScript 函数，不是 HTTP 服务。类型来源 `src/lib/experience.ts`：

| 字段      | 可用值/类型                                                         | 当前意义                     |
| --------- | ------------------------------------------------------------------- | ---------------------------- |
| `topic`   | `relationship` / `career` / `uncertainty`                           | 内容主题                     |
| `need`    | `clarity` / `timing` / `action`                                     | 帮助方向                     |
| `feeling` | UI 中三个固定中文选项                                               | 写入追问句；当前无自由文本框 |
| 返回      | `title`、`observation`、`tension`、`action`、`question`，均为字符串 | 纯示例内容，无概率/报告 ID   |

UI 选项保障当前输入范围；函数并非公开输入安全边界。未来任何网络/自由文本输入必须做运行时校验。输出保持文本渲染，不能把未清洗服务端内容塞进 HTML。

## 生产化的三条边界

1. 主站可以继续静态部署，真实账户/计算/支付由正式产品承接。不要求为了主站重写已有核心服务。
2. 若把真实体验嵌进主站，先定义可信服务边界（必要时 BFF），浏览器不能持有模型或支付私钥，也不能直接读内部计算资料。
3. `src/lib/site.ts` 当前将 CTA 留在方法页。确认正式 HTTPS 产品入口和环境后再替换；不要从查询参数任意构造外跳地址，也不要通过 URL 传递出生信息、问题或结果。

## 需要核心团队提供的能力契约（未实现）

| 能力           | 必须确认的输入/输出语义                           | 失败与安全条件                                 |
| -------------- | ------------------------------------------------- | ---------------------------------------------- |
| 会话/账户      | 是否必须登录、当前身份/权限、会话期限             | 失效重新认证；身份来自服务端而非客户端指定用户 |
| 资料确认       | 各服务的必要资料、历法/时区规则、未知出生时间处理 | 拒绝非法输入；缺失时明确限制；不自动伪造       |
| 计算/报告任务  | 同步或异步、任务标识、版本、完成结果、解释依据    | 任务归属校验、超时、重试/取消语义、幂等        |
| 结果与追问     | 观察/依据/局限/行动的结构，内容格式与流式规则     | 引用不匹配、部分缺失、模型拒答、网络断开       |
| 保存/历史/删除 | 保存同意、归属、列表/详情、删除范围与期限         | 越权读取隔离；删除可见结果与真实处理状态分开   |
| 权益/订单      | 价格来源、币种/周期、税费、权益状态、订单查询     | 不信任浏览器价格；支付返回页不能独自授予权益   |
| 支付回调       | 网关签名、事件去重、订单核对与幂等处理            | 重放/乱序/延迟/伪造回调，审计与对账            |

收到契约后，`API_CONTRACT.md` 必须补齐实际 URL/方法、认证、schema、样例、错误状态、限流、超时、分页、版本、环境和数据保留。这里不预设 endpoint 名、供应商、价格或核心字段名。

## 异步体验状态设计（建议）

UI 语义状态：资料待确认 → 提交中 → 等待结果 → 完成；分支为输入错误、会话过期、限流、连接失败、服务失败、取消/退出。它们不是核心 API 已冻结的枚举名称。

- 提交后防重复操作；服务端对同一次操作定义幂等键和有效期，不能只靠禁用按钮。
- 断网后查询原任务再决定是否重试，避免重复扣费或重新起卦。超时表示“结果未知”，不等于失败。
- 真实等待展示阶段文字；只有后端有可信进度才显示百分比。不用固定动画假装计算。
- 页面刷新后的恢复范围需同时考虑会话和隐私；不要默认把私密资料存在浏览器长期存储。
- 部分数据不足时展示已可确认内容及限制，不自动补全依据；无法生成有效结果时不回退成示例文本伪装成功。
- 付费成功以服务端确认后的权益为准；未确认期间显示处理中并允许查询，不引导反复付款。

## 内容、数据与发布

白皮书源是公开 Markdown；内部 `white_paper/` 不进发布包。每次改正文须同步生成 PDF、构建网页并做一致性检查。当前下载是指纹资源，内容变化后地址变化，不覆盖旧文件制造缓存混乱。

若未来启用分析事件，先决定法律/同意依据及供应商。建议仅记录页面、步骤序号、CTA 标识、错误类别；默认禁止上传问题正文、感受、出生资料、报告内容或身份拼接。前端性能日志也须脱敏。当前没有实施任何埋点。

生产主站还需：正式 canonical/分享图/站点地图及索引策略、真实政策与客服联系入口、监控与告警、内容负责人、CI 环境锁定。不要把这些需求和演示版“构建成功”混为一谈。

## 对接完成的定义

由前端与核心团队共同提供：确认过的 OpenAPI 或等价契约、脱敏成功与错误样例、测试环境、权限矩阵、任务/支付幂等测试、内容依据追溯样例、日志脱敏方案及故障回退说明。然后按 [QA 清单](../handoff/验收与实施任务清单.md) 验证。域内八字字段继续遵守核心团队既有命名规范，不在主站自行翻译或分叉。
