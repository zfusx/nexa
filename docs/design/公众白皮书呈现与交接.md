# 公众白皮书 v0.2：呈现与交接

## 当前交付

当前文稿源：`docs/whitepaper/Nexa公众白皮书_v0.2.md`。PDF：`output/pdf/Nexa公众白皮书_v0.2.pdf`。网页：`src/pages/whitepaper.astro`，沿用 `/whitepaper` 路由。v0.1 保留为历史普通读者版；v0.2 是增加公开公式、符号、验证指标与参考资料的专业版审阅稿。

网页同时提供两个 PDF 版本：v0.2 标记为“当前版本 · 专业数学版”，位于视觉主位；v0.1 标记为“入门参考 · 普通读者版”，作为更轻量的历史参考。两个入口必须说明阅读深度差异，不暗示两版给出不同命理结论，也不能把 v0.1 误标为当前技术状态。

本版定位为普通读者可读的团队审阅稿；设计资料描述的方法与生产已验证能力分别表达。不要在 UI 上移除版本/审阅状态后直接将其包装为最终研究证明。

## 内容层次与视觉

| 区域       | 阅读任务                   | 实现与设计约束                                                 |
| ---------- | -------------------------- | -------------------------------------------------------------- |
| 封面       | 理解 Nexa 研究什么         | 深靛背景、衬线中文标题、版本/日期；标题不使用“科学验证命运”    |
| 首屏说明   | 理解本稿证据范围           | 保留可见说明，不能只藏在页脚或弹窗                             |
| 章节目录   | 快速找到关心的主题         | 七章原生锚点；桌面粘性侧栏；手机单列展开，键盘可操作           |
| 正文       | 把技术与实际问题连接       | 米白阅读底色，正文约 725px 上限、充足行距；三级标题用较深紫色  |
| 章末重点句 | 帮助记住核心观点           | 淡紫引用块；不设计成用户评价或第三方背书                       |
| 数学公式   | 看懂对象、不变量和验证逻辑 | 深靛等宽公式块；只使用公开级通式，不展示内部权重、阈值与规则表 |
| PDF 下载   | 离线阅读、团队传阅         | 明示版本；按钮指向构建打包的同源 PDF，无注册门槛               |
| 末尾入口   | 带着问题体验产品           | 沿用浏览器内微体验；不新增注册、支付或资料提交                 |

十一页 PDF 采用封面加七章连续论文式分页；中文字形嵌入，公式采用等宽拉丁字体，使用矢量文字与几何元素。没有使用伪造评测图、实验照片、资质徽章或抽象“量子芯片”来暗示研究成果。

## 可直接使用的内容方向

- 主标题：“让复杂有章可循，让理解经得起追问。”
- 方法摘要：“用组成几何、条件系统、时间路径、概率模型与可解释 AI 组织传统知识。”使用时附“方法设计”语境，直至上线范围得到确认。
- 数学亮点：Aitchison 几何；布尔门控与有向关系；多尺度状态路径；模糊过渡、扰动稳定率与概率校准。
- 周易亮点：顺序、状态、反馈与概率模型对照。“量子启发”必须连同建模含义呈现。
- 用户价值：解释依据、呈现差异、保留未知、帮助形成可核对的问题。

不得将模拟稳定性说成现实准确率，也不得暗示“五行是已测得的物理能量”“AI 不会出错”“量子技术控制未来”。无真实证据时不添加“最准”“领先”“已验证提升”等比较主张。

## 开发维护

1. 只编辑公开 Markdown 正文；网页编译该文件，PDF 构建器也只读取该文件。
2. 正文改变后，先运行 `python3 scripts/build_whitepaper.py`（Python 环境需有 reportlab；中文字体可通过 `NEXA_BODY_FONT` 和 `NEXA_TITLE_FONT` 指定）。当前本机使用 Codex bundled Python，详见 `TOOLING_GUIDE.md`。
3. PDF 构建器要求七章且总页数在 9-15 页；异常会失败。变更章节数或版本时，应同时维护 PDF 构建器、网页下载提示和版本元数据。
4. 按 PDF 技能流程将生成件渲染为图，逐页检查，随后运行 `npm run build`。Vite 把 PDF 复制为带指纹静态资源，页面下载引用会随构建更新。
5. 不把 `white_paper/` 内部目录复制到 `public/` 或服务器；网站仅引用脱敏后的公开文稿与输出 PDF。
6. 原生锚点、PDF 链接及正文不依赖新增客户端脚本；不增加追踪、Cookie 或第三方字体请求。

## 本轮验收范围

检查十一页中文/公式渲染、段落内容覆盖、网页七章与目录、桌面/手机断点、下载文件一致性、构建、既有体验测试和公开输出敏感模式。验收结果在 `WORKLOG.md`；这些测试仅针对主站与文档，不是核心命理模型评测。

## 后续正式版所需材料

核心团队提供模块上线状态和版本、脱敏的真实输出样例、评测方法与结果；品牌团队审阅文稿语气。确认后形成可公开定稿，再按 `DEPLOYMENT.md` 创建新的可回滚 release。不要在未补证时将“设计要求”改写为“已经验证的能力”。
